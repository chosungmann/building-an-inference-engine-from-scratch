## 1. 한 문장 요약

프로그램을 짜 본 독자가 이 한 권만 읽고, 추론 엔진 `badak`을 Rust로 직접 만들어 LLM·비전·음성·이미지 생성·멀티모달 모델을 끝까지 돌리고, llama.cpp와 LiteRT 같은 실전 엔진과 성능을 비교해 차이의 원인을 설명할 수 있게 되는 책입니다.

## 2. 왜 이 책인가

AI 추론은 이제 모델 연구자만의 일이 아닙니다. 모델을 제품에 싣는 일은 메모리 배치, 캐시, SIMD, 스레딩, 파일 포맷, 수치 정밀도 같은 시스템 엔지니어링 문제이고, 이는 소프트웨어 엔지니어가 이미 하는 일과 맞닿아 있습니다.

그런데 기존 자료는 세 갈래로 나뉘어 있습니다.

- **모델 쪽 자료**는 PyTorch로 모델을 "쓰는" 법을 가르치지만, 그 밑에서 무슨 일이 일어나는지는 다루지 않습니다.
- **엔진 쪽 자료**는 llama.cpp나 LiteRT의 소스 코드와 흩어진 블로그 글뿐이라, 배경지식 없이는 읽기 어렵습니다.
- **운영 쪽 자료**는 데이터센터에서 기존 엔진을 설정하고 운영하는 법을 개념 수준에서 다루지만, 엔진 내부를 직접 만들어 보게 하지는 않습니다.

이 책은 그 사이를 메웁니다. 엔진을 직접 만들면 "왜 이렇게 설계되었는가"를 몸으로 이해하게 되고, 실전 엔진과 숫자로 비교하면 "무엇이 아직 부족한가"가 드러납니다.

## 3. 독자

**대상**: 추론 엔진이 안에서 무슨 일을 하는지 궁금하고, 한 가지 언어로 프로그램을 짜 본 사람. AI 인퍼런스 엔지니어링으로 도메인을 넓히려는 소프트웨어 엔지니어에게 가장 잘 맞지만, 경력의 길이를 조건으로 두지 않습니다. 이 책이 하지 않는 것은 프로그래밍의 기초를 가르치는 일뿐입니다.

| 구분 | 내용 |
|---|---|
| 전제하는 것 | 한 가지 언어로 프로그램을 짜 본 경험, 명령줄과 Git 사용 |
| 전제하지 않는 것 | 머신러닝·딥러닝 지식, 선형대수, PyTorch 경험, SIMD·GPU 프로그래밍 경험. 캐시·스레드·가상 메모리 같은 시스템 지식은 알면 빨리 읽히지만, 책이 쓰는 만큼은 그 장에서 설명합니다. |
| Rust | 다른 언어를 써 봤으면 따라올 수 있게 씁니다. 이 책이 쓰는 Rust 기능(소유권, 트레이트, `unsafe`, SIMD 내장 함수)은 부록에서 정리합니다. |

**책을 덮은 독자가 할 수 있는 일**

1. 신경망 모델이 파일에서 출력까지 가는 전 과정을 바이트 단위로 설명합니다.
2. 새 모델 아키텍처를 받아 스스로 추론 코드를 작성하고, 레퍼런스와 수치를 대조해 검증합니다.
3. 추론 성능을 측정하고, 병목이 연산인지 메모리인지 계산으로 가려내고, 커널·양자화·메모리·스레딩 수준에서 개선합니다.
4. 최적화가 출력 품질을 해치지 않았는지 측정으로 확인합니다.
5. llama.cpp, LiteRT, ONNX Runtime, ExecuTorch 같은 엔진의 소스 코드를 읽고 설계 결정을 평가합니다.
6. 서버, 폰, 브라우저 중 어디에서 돌릴지와 엔진·양자화 방식·하드웨어 백엔드를 제품 요구사항에 맞춰 선택하고 그 근거를 댑니다.

## 4. 목표, 비목표, 실패 조건

**목표**
- 자기완결성: 필요한 수학, 신경망 지식, 시스템 지식을 모두 책 안에서 가르칩니다.
- 완주: 각 분야에서 잘 알려진 실제 모델을 전처리부터 최종 출력까지 돌립니다.
- 검증: 모든 구현을 레퍼런스(PyTorch 등)와 수치로 대조합니다.
- 비교: 모든 분야에서 실전 엔진과 벤치마크를 비교하고 차이의 원인을 분석합니다.
- 실행 가능성: 책의 모든 코드는 저장소에서 그대로 빌드·실행·테스트됩니다.
- 검증 가능성: 저자가 모든 내용을 직접 확인할 수 있도록, 수치는 명령 하나로 재현되고 외부에서 온 사실에는 출처를 답니다.

**비목표**
- 학습(training)은 다루지 않습니다. 가중치가 어디서 오는지 이해하는 데 필요한 만큼만 설명합니다.
- 실전 엔진을 대체하는 제품을 만들지 않습니다. 목적은 이해입니다.
- 모든 연산자·모든 모델을 지원하지 않습니다. 다루는 모델에 필요한 것만 구현합니다.
- 데이터센터 운영(컨테이너, 오토스케일링, 멀티 클라우드)은 설계 분석까지만 다룹니다.

**실패 조건** (기술적으로 동작해도 이러면 실패입니다)
- 본문 코드와 저장소 코드가 달라 독자가 따라 하다 막히는 경우.
- 벤치마크 수치를 실제로 측정하지 않고 적는 경우.
- LLM 이외 분야가 "이런 것도 있다" 수준의 소개로 끝나는 경우.
- 외부 자료를 읽어야만 이해되는 대목이 남는 경우.
- 존재하지 않거나 내용이 다른 문헌을 인용하는 경우.

## 5. 접근 방식

### 5.1 검토한 뼈대 세 가지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. LLM 단일 집중 | LLM 하나만 끝까지 판다 | 가장 깊고 짧다 | 분야를 두루 다룬다는 목표를 포기한다 |
| B. 분야별 동등 병렬 | 분야마다 처음부터 독립적으로 다룬다 | 어느 분야도 얕지 않다 | 커널·양자화 설명이 분야마다 반복되고 분량이 두세 배가 된다 |
| **C. 공통 기초 + 분야별 완주 (채택)** | 공통 기술은 한 번 깊게, 분야 장은 고유한 내용에 집중 | 반복 없이 깊이와 폭을 모두 얻는다 | 책이 크다 (52장 이상) |

**C를 고른 이유**: 저자는 "모던 AI 인퍼런스 엔지니어링을 속속들이" 다루기를 원했고, 분야가 얕아지는 것을 우려했습니다. C는 Géron의 *Hands-On Machine Learning*과 같은 구조로, 분야가 얕아지는 문제를 아래의 동일 기준으로 막습니다.

### 5.2 모든 분야 장의 동일 기준

1. 잘 알려진 실제 모델을 전처리부터 최종 출력까지 완주합니다.
2. 레퍼런스 구현과 중간 텐서·최종 출력을 수치로 대조합니다.
3. 해당 분야의 실전 엔진과 같은 기계에서 벤치마크하고, 차이의 원인을 프로파일로 설명합니다.
4. 그 분야에서만 필요한 기술은 생략 없이 직접 구현합니다.
5. 본문의 주장마다 근거 자료를 각주로 달아, 독자가 원하면 더 깊이 들어갈 수 있게 합니다.

### 5.3 엔진을 두 가지 방식으로 만든다

실전 엔진은 크게 두 계열이고, 이 차이를 아는 것이 이 분야의 핵심입니다. 이 책은 둘 다 만듭니다.

| 계열 | 대표 | 방식 | 이 책에서 |
|---|---|---|---|
| 모델 코드 직접 작성형 | llama.cpp, whisper.cpp | 아키텍처를 엔진 코드로 직접 쓰고, 파일에는 가중치만 둔다 | 2부(LLM)와 음성·이미지 생성 장 |
| 그래프 해석형 | LiteRT, ONNX Runtime, ExecuTorch | 파일에 연산 그래프가 들어 있고, 엔진은 범용 해석기다 | 4부에서 `.tflite` 해석기를 구현 |

두 계열 위에 7부에서 세 번째 계열(ML 컴파일러)을 설명합니다.

### 5.4 레퍼런스 프레임워크의 역할

PyTorch와 TensorFlow는 만들 대상이 아니라 **정답지이자 출발점**으로 다룹니다.

- **PyTorch**: 모든 모델의 수치 정답을 만드는 기준입니다. 층별 중간 텐서를 덤프하는 작은 Python 스크립트를 제공합니다. "왜 PyTorch를 그대로 배포하지 않는가"도 한 장에서 측정과 함께 설명합니다.
- **TensorFlow**: LiteRT(구 TensorFlow Lite)의 계보와 변환기, `.tflite` 포맷을 이해하는 맥락으로 다룹니다.

독자는 Python을 몰라도 됩니다. 스크립트는 실행만 하면 되고, 결과 파일은 공개된 곳(Hugging Face Hub)에서 내려받을 수도 있습니다.

### 5.6 참고한 책과 이 책의 위치

Philip Kiely의 *Inference Engineering* (Baseten Books, 2026)을 검토했습니다. 데이터센터 GPU 위에서 기존 엔진(vLLM, SGLang, TensorRT-LLM)을 써서 생성형 모델을 운영하는 법을 개념 수준에서 정리한 책으로, 코드는 없습니다. 이 책과는 상호 보완 관계입니다.

### 5.7 노트북 실습 (Colab)

엔진은 각자의 PC에서 Rust로 빌드하고 테스트합니다. 그와 별도로, 노트북이 더 적합한 실습은 Jupyter 노트북으로 제공하고 Google Colab에서 바로 열 수 있게 합니다.

**노트북으로 제공하는 것**

| 용도 | 예 | 이유 |
|---|---|---|
| 개념 탐색 | 행렬 연산, 어텐션 가중치, 양자화 오차, 멜 스펙트로그램, 확산 과정을 그림으로 확인 | 값을 바꿔 가며 그림을 보는 데는 노트북이 낫습니다. |
| 정답 만들기 | PyTorch로 층별 정답 텐서 덤프 | 독자가 Python 환경을 설치하지 않아도 됩니다. |
| 모델 변환 | `.tflite`, GGUF, ONNX로 내보내기 | 변환 도구가 Python 생태계에 있습니다. |
| 학습이 필요한 실습 | 양자화 인식 학습, 가지치기, 증류 (46장) | GPU가 필요하고, Colab이 무료 GPU를 제공합니다. |
| NVIDIA GPU 체험 | vLLM 등 데이터센터 엔진 실행 (42장) | 이 책의 기준 기계에 없는 NVIDIA GPU를 독자가 직접 써 볼 수 있습니다. |

**노트북으로 하지 않는 것**
- 엔진 구현: badak의 코드는 저장소의 Rust 소스가 유일한 원본입니다.

## 9. 코드와 저장소

### 9.1 원칙

- **엔진은 표준 라이브러리만 사용합니다.** 텐서, 커널, 파서, 토크나이저, 스레드 풀, HTTP 서버를 모두 직접 씁니다.
- **예외는 명시합니다.** 추론의 본질이 아닌 경계 부분만 외부 크레이트를 허용하고, 허용 목록을 책에 싣습니다. 현재 목록은 GPU 접근(`wgpu`), 브라우저 연결(`wasm-bindgen`), 이미지 파일 디코딩입니다.
- **단계별 구현을 지우지 않습니다.** 단순한 행렬 곱, 블로킹 버전, SIMD 버전이 모두 저장소에 남아 벤치마크에서 서로 비교됩니다. 독자는 각 최적화의 기여를 직접 측정합니다.
- **본문 코드는 소스에서 끌어옵니다.** mdBook의 포함 기능으로 실제 소스 파일의 구간을 본문에 넣어, 책과 코드가 어긋나지 않게 합니다.

**알려진 한계**
- 책의 수치는 M4 Max 기준이며, 다른 기계에서는 절대값이 다르고 엔진 간 순위가 바뀔 수 있습니다. 책에 이 점을 명시합니다.
- 노트북은 발열과 백그라운드 작업에 따라 수치가 흔들립니다. 오래 걸리는 측정은 맥을 다른 용도로 쓰지 않을 때 실행합니다.

### 9.4 성능 목표

숫자는 약속이 아니라 가설이며, 책에는 실제 측정값을 그대로 싣습니다.

- 2부 끝: 동작하지만 llama.cpp보다 수십 배 느린 상태를 그대로 보여줍니다.
- 3부 끝: 같은 양자화의 CPU 추론에서 llama.cpp에 근접하는 것을 목표로 합니다.
- 격차가 남는 지점은 숨기지 않고 53장에서 원인별로 분류합니다.
